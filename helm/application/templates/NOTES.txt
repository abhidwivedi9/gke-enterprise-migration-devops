------------------------------------------------------------------------
STEP 1 — Did the rollout actually finish?

  kubectl rollout status deployment/{{ include "orders-api.fullname" . }} \
    -n {{ .Release.Namespace }} --timeout=180s

  "helm install" returning 0 means the MANIFESTS were accepted, not that the
  pods are running. Without --wait, Helm does not check. This is the number
  one reason a pipeline reports SUCCESS on a deploy that never came up.

------------------------------------------------------------------------
STEP 2 — Are the pods healthy?

  kubectl get pods -n {{ .Release.Namespace }} \
    -l app.kubernetes.io/instance={{ .Release.Name }} -o wide

  Look for READY 1/1 and RESTARTS 0. READY 0/1 with STATUS Running means the
  readiness probe is failing — the container is up but serving nothing.

------------------------------------------------------------------------
STEP 3 — VERIFY THE VERSION. Never skip this.

  kubectl get pods -n {{ .Release.Namespace }} \
    -l app.kubernetes.io/instance={{ .Release.Name }} \
    -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.containers[0].image}{"\n"}{end}'

  Then ask the running process itself, which is the only real ground truth:

  kubectl port-forward -n {{ .Release.Namespace }} \
    svc/{{ include "orders-api.fullname" . }} 8080:{{ .Values.service.port }} &
  curl -s localhost:8080/version

  Expect application_version = {{ .Chart.AppVersion }}.
  If it does not match, STOP and read docs/VERSION_VERIFICATION.md.

  Or run the whole chain in one command:
    ./scripts/verify-version.sh -n {{ .Release.Namespace }} -r {{ .Release.Name }} -v {{ .Chart.AppVersion }}

------------------------------------------------------------------------
STEP 4 — Reach the service (no cost, no load balancer)

  kubectl port-forward -n {{ .Release.Namespace }} \
    svc/{{ include "orders-api.fullname" . }} 8080:{{ .Values.service.port }}
  curl -s localhost:8080/api/orders | jq
